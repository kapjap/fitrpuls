## Выполненные изменения
### Данные и основная тренировка
1. `DatabaseProvider`: единый экземпляр Room вместо отдельных builder в шести Activity; fallbackToDestructiveMigration удалён.
2. Версия базы 6→7: новая `session_drafts` с составным ключом `(userId, workoutId)`; `completed_exercises.warmup NOT NULL DEFAULT 0`; nullable `completed_workouts.source_session` с уникальным индексом. Старые строки сохраняются.
3. `SessionSnapshot`/`SessionRepository`: снимок фактических упражнений и отдельных подходов в Room; сериализация Gson; последовательный executor; сохранение по изменениям/уходу с экрана/периодически для таймера.
4. `WorkoutSessionActivity`: восстановление при открытии того же шаблона; изменение веса/повторов каждого подхода, независимое выполнение, разминка, добавление подходов. Ограничение в пять подходов убрано.
5. Завершение сохраняет **только отмеченные подходы**, одной транзакцией с удалением черновика. UUID + unique index защищают от повторного завершения. Запоздалая запись уже завершённого UUID не воссоздаёт черновик.
6. Создание шаблона транзакционно; сохранение блокирует повторный клик; удаление шаблона с черновиком запрещено, обычное удаление транзакционно.
7. Исторические показатели 2.0 не переписываются: старая версия могла сохранять плановые подходы, фактических данных для исправления нет.

### Навигация, реальные данные, оформление
8. Главная: недельные количество/минуты/объём, последняя тренировка и пустое состояние из Room LiveData через `DashboardViewModel`.
9. `MainNavigation`: нижние направления Главная / Тренировки / Прогресс / Залы / Профиль. Существующие Activity сохранены; это не полный перевод приложения на Fragments/MVVM.
10. `ProgressInsight`: описательное сравнение максимального рабочего веса одного имени упражнения в двух последних тренировках; разминка исключена, ограничения указаны. Нет назначения нагрузки и рейтинга разных движений.
11. Material 3 day/night токены: графит/лайм, семантические поверхности/текст, типографические и отступные ресурсы. Новый практичный layout активной тренировки: список подходов, компактный отдых, действие завершения.
12. Legacy профиль/карты/заметки/новости/вход ещё не приведены к единому новому дизайну. Не считать их полностью переделанными. `design/home-preview.html` устарел и НЕ отражает текущий Android UI.

### ANTI-GYM: небольшой характер поверх функциональности
13. App label и бренд главной — ANTI-GYM, идентификатор приложения не менялся.
14. `CharacterPreferences`/`CharacterSettings`: Normal/Bro/Chaos, по умолчанию Bro; юмор и эффекты отключаются отдельно; настройки по UID. Реплики только на главной: вероятность 20%, минимум 72 часа между показами. На экране тренировки шуток нет.
15. `TrainingXp`: 100 XP за уникальный день UTC с выполненной тренировкой, максимум 100/день; уровень = 1 + floor(XP/500). Не зависит от веса/повторов, вычисляется из истории идемпотентно. Текстовый LEVEL UP 450 мс, опциональный, учитывает системное отключение анимаций. Полноценный экран достижений/PR-анимации ещё не сделан.

### Качество/безопасность
16. Убрано логирование полного GNews URL с API key. Production ключи/keystore не трогали.
17. Локальное удаление аккаунта теперь включает историю/подходы/черновики транзакционно. **Полное удаление облачных данных НЕ исправлено**: исходный flow удаляет Auth раньше Notes/NoteContents; это отдельный P0 backend этап.
18. Добавлено объявление POST_NOTIFICATIONS: receiver уже проверял runtime permission. Автоматический запрос разрешения не добавляли. Исправлены lint errors совместимых tint атрибутов.
19. Включён ViewBinding (полная конвертация legacy экранов ещё не сделана), экспорт Room schema 7. Версия приложения `2.1-dev`, versionCode 3, minSdk 24.

Android platform 35/build-tools 35 загружены с dl.google.com, проверены checksums из официального repository XML. Файлы в `/workspace/toolchains` вне Git.

В `/workspace/.gradle/gradle.properties` настроены proxy host/port без секретов, 2 workers, heap 2 GiB, trustStore `/etc/ssl/certs/java/cacerts`. Проверка TLS не отключалась. В `local.properties` только локальный путь SDK (ignored). `ANDROID_USER_HOME` нужен: `/home/agent/.android` read-only. Сначала новый sdkmanager оказался deprecated launcher с попыткой записи в read-only каталог; SDK установлен из проверенных официальных архивов. Oracle latest JDK URL дал 404, использован проверенный Temurin.

Лог последнего прогона `/tmp/fitrpuls-build.log` временный. После сброса машины он может отсутствовать; повторить команду. Зависимости/SDK процессы не считать запущенными из snapshot.

## Известные ограничения / риски
- Нет cloud sync тренировок, outbox, conflict resolution и серверных entitlements. Firebase для существующих функций сохранён; не заявлять полную синхронизацию.
- Незавершённый шаблон создания не переживает process death; восстановление реализовано для активной тренировки.
- Асинхронное сохранение последнего изменения может не успеть при немедленном kill. Нужен явный dirty/saving/saved/error UI и lifecycle/process-death тест.
- Таймер после перезапуска использует wall clock; перевод часов может исказить время. Во время открытой тренировки используется elapsedRealtime.
- Имена упражнений пока legacy-идентичность; одинаковое название может скрывать разную технику/оборудование. Не выдавать сравнение за точную оценку силы.
- Недостающие миграции <6 не придуманы. Нужен настоящий fixture базы установленного APK 2.0 и проверка подписи обновления.
- Новые строки пока частично hardcoded; необходима локализация/доступность. Адаптивная разметка ещё требует настоящего визуального тестирования.
- XP локально вычисляется по дням UTC; удаление истории уменьшает XP; это не глобальный защищённый ledger. Full RPG achievement screen не реализован.
- Legacy удаление аккаунта/backup/ключи API требуют security/backend этапа до релиза.
- Ничего не опубликовано в Google Play, платежи не подключены. Debug APK с другой подписью не обновляет production installation — не удалять приложение для «проверки миграции».
