# Аудит исходной версии 2.0

Проверены модели/DAO, создание и выполнение тренировок, история/статистика, главный экран, навигация, профиль/удаление аккаунта, ThemeManager, точки обращения к Firebase, карты/новости, manifest, Gradle и ресурсы. Это первичный аудит, не независимый полный security review.

## Исправлено в текущем этапе
- Удалён fallbackToDestructiveMigration; Room централизован и получает additive migration 6→7.
- Завершение раньше записывало каждый запланированный подход; теперь учитываются только отмеченные фактические значения.
- История и упражнения сохраняются одной транзакцией. Создание шаблона также транзакционно.
- Черновики изолированы по UID и шаблону; шаблон проверяется на принадлежность при начале сессии.
- Убрано ограничение интерфейса пятью подходами.
- Новости больше не выводят полный URL с API key в лог.
- При локальном удалении аккаунта очищаются также история, её упражнения и черновики; операция транзакционная.
- Убрана визуальная сравнительная шкала разных упражнений; рабочие веса сравниваются по названию упражнения, с явными ограничениями.

## Открытые риски
1. Account deletion: существующий код сначала удаляет Firebase Auth, облачные Notes/NoteContents и профиль не удаляет. Нужна серверная оркестрация до заявления о полном удалении. Не проверяли production Rules, они отсутствуют в репозитории.
2. Ключи/API конфигурация присутствуют в исходном проекте. Значения не копируются в документацию. Keystore и production config не удалялись/не заменялись. Владельцу проверить ограничения Android package/certificate и секреты news API; публичный клиент не защищает серверный API key.
3. Активные сессии сохраняются локально, но подтверждение записи UI ещё недостаточно явное. Нет облачной синхронизации и conflict UI.
4. Нет исторических Room schemas <6. Произвольные миграции старых версий не придумываем. Версию установленной базы и подпись APK нужно подтвердить на настоящем устройстве.
5. Backup включён исходным приложением; требуется политика исключения чувствительных данных и проверка восстановления между аккаунтами.
6. Яндекс Search/MapKit сохранены. Возможности/лицензия API, квоты, геолокация по запросу, маршруты/поиск города и избранное требуют отдельного этапа. Не создавали ложные рейтинги/инвентарь.
7. Новости GNews зависят от внешнего сервиса/ключа, актуальная работоспособность не подтверждена.
8. Legacy статистика могла содержать плановые значения, исправление новых сессий не восстанавливает прошлую фактическую нагрузку.
9. Профиль/вход/некоторые Activity ещё используют legacy потоки/lifecycle паттерны; требуется следующий проход.
